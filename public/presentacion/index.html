02 / 10 Visión del Producto

👁️ ¿Qué es Trivia War?

Una plataforma web de trivia donde los jugadores eligen sus propias temáticas y la IA genera preguntas personalizadas al instante. Gratuito en su núcleo, con monetización en personalización y pases de temporada.

🤖

Motor de IA Multi-API

Gemini, Groq, Cohere, Hugging Face y OpenRouter en cadena de fallback. Si uno falla, el siguiente toma el control.

🎮

Dos Modos de Juego

Entrenamiento: 5 preguntas individuales.
Multijugador: Salas en tiempo real con WebSocket.

📊

Ranking y Estadísticas

Sistema de puntuación global con Firestore. Cada partida suma puntos y se refleja en el ranking en vivo.

💬

Chat Global en Vivo

Chat integrado con WebSocket. Los jugadores pueden comunicarse mientras esperan partida o después de jugar.

🔐

Autenticación Completa

Registro, login, Google OAuth, recuperación de contraseña y verificación de email con Firebase Auth.

🎵

Experiencia Inmersiva

Música de fondo dinámica, efectos de sonido por acción y transiciones suaves entre pantallas.

🎤 Ver guion del orador

"Trivia War nace con una premisa clara: democratizar la creación de contenido de trivia mediante inteligencia artificial. A diferencia de otros juegos donde las preguntas son fijas y se repiten, aquí cada partida es única porque la IA genera las preguntas en tiempo real basándose en las temáticas que eligen los jugadores."

"El modelo de negocio es igualmente estratégico: la generación de preguntas por IA es completamente gratuita para atraer usuarios, y la monetización viene por el lado de personalización de avatares, pases de temporada y reglas especiales de sala. Esto nos permite escalar sin fricción."

"Técnicamente, el proyecto se compone de dos repositorios: un backend en Node.js con Express y Socket.io, y un frontend en Angular 17 con standalone components. La base de datos es Firestore de Firebase, y la autenticación también corre sobre Firebase Auth."

07 / 10 Trazabilidad

📌 Trazabilidad 1: HU-01 — Fallback de 5 APIs de IA

Criterio de aceptación: "Si una API de IA falla, el sistema debe intentar automáticamente con la siguiente sin interrumpir la experiencia del usuario."

📄 Implementación triviawar-back/src/services/aiService.js 
// Orquestador con 5 planes de fallback (A→E)
const runWithFallbacks = async (sysInstruction, prompt, tematicas, temperature, expectedCount) => {
  const plans = [
    { name: "Plan A", label: `Gemini (${GEMINI_MODEL})`, fn: () => tryGemini(...) },
    { name: "Plan B", label: "Groq (Llama 3 70B)", fn: () => tryGroq(...) },
    { name: "Plan C", label: "Cohere (Command R)", fn: () => tryCohere(...) },
    { name: "Plan D", label: "Hugging Face (Llama 8B)", fn: () => tryHF(...) },
    { name: "Plan E", label: "OpenRouter (LFM)", fn: () => tryOpenRouter(...) },
  ];

  for (const plan of plans) {
    try {
      const { text, duration } = await plan.fn();
      const preguntas = normalizeQuestions(JSON.parse(cleanJsonResponse(text)), tematicas);
      if (expectedCount && preguntas.length !== expectedCount) continue;
      return { success: true, preguntas, aiUsada: plan.label, duration };
    } catch (err) {
      console.error(`❌ [${plan.name}] ${err.message}`);
    }
  }
  return { success: false, message: "Todos los motores de IA fallaron." };
};

📌 Trazabilidad 2: HU-04 — Protección contra doble clic en inicio de partida

Criterio de aceptación: "Si dos jugadores hacen clic en 'Iniciar partida' simultáneamente, el juego no debe generar preguntas duplicadas ni romperse."

📄 Implementación triviawar-back/src/services/gameService.js 
const startGame = async (roomCode) => {
  const room = await roomRepository.getRoom(roomCode);
  if (!room) throw new Error('Sala no encontrada');

  // 🛡️ PROTECCIÓN: Evitar múltiples llamadas simultáneas a la IA
  if (room.estado === 'generating' || room.estado === 'playing') {
    console.warn(`⚠️ La sala ${roomCode} ya está generando preguntas.`);
    throw new Error('El juego ya se está iniciando, por favor espera...');
  }

  // 🔒 BLOQUEO: Marcar sala como "generando"
  await roomRepository.updateRoom(roomCode, { estado: 'generating' });

  // Generar preguntas con IA
  const resultAI = await aiService.generateQuestions(listaTematicas);
  // ...
};

📌 Trazabilidad 3: HU-02 — Taxonomía de dificultad con puntaje diferenciado

Criterio de aceptación: "Cada nivel de dificultad debe tener una definición estricta y un puntaje base diferente: Baby=10pts, Conocedor=20pts, Killer=30pts."

📄 Implementación triviawar-back/src/services/aiService.js + triviawar-front/src/app/componentes/arena/arena.ts 
// BACKEND: Taxonomía de dificultad enviada a la IA como system instruction
const DIFFICULTY_TAXONOMY = `
🍼 NIVEL BABY: Pregunta que CUALQUIER persona respondería.
🧠 NIVEL CONOCEDOR: Requiere interés REAL en el tema.
💀 NIVEL KILLER: Solo un experto con años de experiencia.

REGLA: Campo "dificultad": exactamente 'baby', 'conocedor' o 'killer'.
`;

// FRONTEND: Puntaje diferenciado por dificultad
let puntosBase = 10;
if (this.preguntaActualObj.dificultad === 'conocedor') puntosBase = 20;
else if (this.preguntaActualObj.dificultad === 'killer') puntosBase = 30;
this.puntaje += puntosBase;
🎤 Ver guion del orador

"Esta es la slide más importante de la presentación. Aquí demostramos que no solo planificamos, sino que cada criterio de aceptación se tradujo en código real y verificable."

"El primer fragmento muestra el orquestador de fallback de IA. Cuando un jugador elige una temática, el sistema intenta con Gemini primero. Si Gemini falla (timeout de 8 segundos), automáticamente pasa a Groq, luego a Cohere, Hugging Face y finalmente OpenRouter. El usuario nunca ve una pantalla de error."

"El segundo fragmento es una joya de gestión de riesgos. Durante las pruebas, descubrimos que dos jugadores podían hacer clic en 'Iniciar partida' casi al mismo tiempo, lo que generaba dos llamadas a la IA. La solución fue un bloqueo a nivel de estado de sala: cuando alguien inicia, la sala pasa a estado 'generating' y cualquier otro intento es rechazado."

"El tercer fragmento muestra cómo la taxonomía de dificultad no es solo un concepto de diseño, sino que está codificada tanto en el backend (como instrucción de sistema para la IA) como en el frontend (para calcular el puntaje). Esto asegura consistencia en toda la aplicación."
